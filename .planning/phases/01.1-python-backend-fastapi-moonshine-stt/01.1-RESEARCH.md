# Phase 1.1: Python Backend: FastAPI + Moonshine STT - Research

**Researched:** 2026-03-12
**Domain:** Python backend (FastAPI, Moonshine Voice STT, speaker diarization)
**Confidence:** MEDIUM

## Summary

This phase builds a Python FastAPI backend at localhost:8000 that the existing Next.js frontend proxy routes call. The backend must handle audio file upload, STT transcription via Moonshine Voice, speaker diarization, and transcript retrieval. The API contract is already defined by the frontend proxy code: `POST /recordings`, `GET /recordings/{id}/status`, `GET /recordings/{id}/transcript`.

Moonshine Voice (`moonshine-voice` pip package, v0.0.49) is the locked STT choice. It runs on CPU via OnnxRuntime, supports file-based transcription by feeding audio chunks to a Transcriber, and claims built-in speaker identification. However, Moonshine Voice's diarization is described as "not robustly evaluated" and still maturing. The safer approach is to use Moonshine Voice for STT and pyannote.audio for speaker diarization -- pyannote is the proven, battle-tested solution the existing allure-ai repo already uses (via WhisperX). Pyannote 3.1 on MPS (Apple Silicon) processes 45 min of audio in ~3 minutes, which meets the performance targets.

**Primary recommendation:** Use `moonshine-voice` for STT transcription + `pyannote.audio` with `speaker-diarization-3.1` for diarization. Use `ffmpeg` via subprocess for audio format conversion. Use `asyncio.Queue` for sequential job processing.

### Pattern 1: Async Job Queue with asyncio
**What:** Use `asyncio.Queue` with a background worker task that processes one job at a time.
**When to use:** Sequential processing on a single machine with predictable memory usage.
**Example:**
```python
import asyncio
from uuid import uuid4

# In-memory job store
jobs: dict[str, dict] = {}
job_queue: asyncio.Queue = asyncio.Queue()

async def process_worker():
    """Background worker that processes one job at a time."""
    while True:
        job_id = await job_queue.get()
        jobs[job_id]["status"] = "processing"
        try:
            result = await asyncio.to_thread(run_transcription, job_id)
            jobs[job_id]["status"] = "completed"
            jobs[job_id]["result"] = result
        except Exception as e:
            jobs[job_id]["status"] = "failed"
            jobs[job_id]["error"] = str(e)
        finally:
            job_queue.task_done()
```

### Pattern 2: FastAPI Lifespan for Model Loading
**What:** Load Moonshine and pyannote models once at startup using FastAPI's lifespan context manager.
**When to use:** Heavy models that should persist across requests.
**Example:**
```python
from contextlib import asynccontextmanager
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup: load models
    app.state.transcriber = load_moonshine_model()
    app.state.diarization = load_pyannote_pipeline()
    # Start background worker
    worker_task = asyncio.create_task(process_worker())
    yield
    # Shutdown: cleanup
    worker_task.cancel()

app = FastAPI(lifespan=lifespan)
```

### Pattern 3: Moonshine Voice File Transcription
**What:** Feed audio to Moonshine Transcriber in chunks, collect TranscriptLine results.
**When to use:** Transcribing pre-recorded audio files (not live microphone).
**Example:**
```python
from moonshine_voice import Transcriber, TranscriptEventListener, get_model_for_language, load_wav_file

class FileTranscriptListener(TranscriptEventListener):
    def __init__(self):
        self.lines = []
        self.current_line = None

    def on_line_started(self, line):
        self.current_line = line

    def on_line_text_changed(self, line):
        self.current_line = line

    def on_line_completed(self, line):
        self.lines.append(line)

model_path, model_arch = get_model_for_language("en")
listener = FileTranscriptListener()
transcriber = Transcriber(
    model_path=model_path,
    model_arch=model_arch,
    listener=listener
)

audio_data, sample_rate = load_wav_file("recording.wav")
transcriber.start()
chunk_size = int(0.1 * sample_rate)
for i in range(0, len(audio_data), chunk_size):
    transcriber.add_audio(audio_data[i:i+chunk_size], sample_rate)
transcriber.stop()

# listener.lines now contains all TranscriptLine objects
```

### Pattern 4: Pyannote Diarization + Moonshine Alignment
**What:** Run pyannote diarization on the audio to get speaker segments, then align with Moonshine transcript lines by timestamp overlap.
**When to use:** Combining separate STT and diarization systems.
**Example:**
```python
from pyannote.audio import Pipeline
import torch

def run_diarization(audio_path: str) -> list[dict]:
    pipeline = Pipeline.from_pretrained(
        "pyannote/speaker-diarization-3.1",
        use_auth_token="HF_TOKEN"
    )
    # Use MPS on Apple Silicon for speed
    device = torch.device("mps" if torch.backends.mps.is_available() else "cpu")
    pipeline.to(device)

    diarization = pipeline(audio_path)
    segments = []
    for turn, _, speaker in diarization.itertracks(yield_label=True):
        segments.append({
            "start": turn.start,
            "end": turn.end,
            "speaker": speaker
        })
    return segments

def align_transcript_with_speakers(transcript_lines, diarization_segments):
    """Assign speaker labels to transcript lines by timestamp overlap."""
    for line in transcript_lines:
        best_speaker = None
        best_overlap = 0
        for seg in diarization_segments:
            overlap_start = max(line.start_time, seg["start"])
            overlap_end = min(line.end_time, seg["end"])
            overlap = max(0, overlap_end - overlap_start)
            if overlap > best_overlap:
                best_overlap = overlap
                best_speaker = seg["speaker"]
        line.speaker = best_speaker or "Unknown"
    return transcript_lines
```

### Anti-Patterns to Avoid
- **Reading UploadFile in BackgroundTask:** The file handle is closed after the response is sent. Read file bytes in the endpoint handler, write to disk, then pass the file path to the background task.
- **Loading models per-request:** Moonshine and pyannote models are large. Load once at startup via lifespan, not per-request.
- **Blocking the event loop:** STT and diarization are CPU-intensive. Always use `asyncio.to_thread()` to run them in a thread pool.
- **Hardcoding speaker count:** Use pyannote's auto-detection, not a fixed number. The CONTEXT decisions require auto-detection.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Audio format conversion | Custom audio decoder | ffmpeg via subprocess | Handles all codecs, battle-tested, no Python memory issues |
| Speaker diarization | Custom clustering | pyannote.audio | Neural diarization is extremely complex; pyannote is SOTA |
| Voice activity detection | Energy-based VAD | Moonshine Voice built-in VAD | Integrated into the transcription pipeline |
| CORS handling | Manual headers | FastAPI CORSMiddleware | Handles preflight, origins, methods correctly |
| Multipart parsing | Manual form parsing | FastAPI UploadFile + python-multipart | Handles streaming, temp files, validation |

**Key insight:** The transcription pipeline has exactly two complex components (STT and diarization) -- both should use proven libraries. Everything else (queue, storage, API) is straightforward FastAPI.

## Common Pitfalls

### Pitfall 1: UploadFile Closed in Background Task
**What goes wrong:** FastAPI closes the UploadFile handle after the response is sent. If you pass it to a BackgroundTask, reading fails.
**Why it happens:** The ASGI lifecycle closes request resources after response.
**How to avoid:** Read file bytes in the endpoint, save to disk immediately, pass file path to background processing.
**Warning signs:** `ValueError: I/O operation on closed file` in background task logs.

### Pitfall 2: Blocking the Event Loop with STT
**What goes wrong:** Moonshine and pyannote are CPU-bound. Running them directly in an async handler blocks all other requests.
**Why it happens:** Python's GIL + async event loop are single-threaded.
**How to avoid:** Use `asyncio.to_thread(run_transcription, ...)` to offload to thread pool.
**Warning signs:** Status endpoint becomes unresponsive during transcription.

### Pitfall 3: Pyannote HuggingFace Auth Token
**What goes wrong:** pyannote/speaker-diarization-3.1 requires accepting terms on HuggingFace and providing an auth token.
**Why it happens:** Model is gated behind HuggingFace terms of use.
**How to avoid:** Accept terms at huggingface.co/pyannote/speaker-diarization-3.1, create HF token, set as environment variable. Alternatively, use `pyannote/speaker-diarization-community-1` which may not require auth (verify).
**Warning signs:** 401 errors during pipeline download.

### Pitfall 4: WebM Format Not Directly Supported
**What goes wrong:** Moonshine Voice expects WAV audio. WebM from browser recording won't load directly.
**Why it happens:** Browser MediaRecorder outputs WebM/Opus; STT models expect PCM WAV.
**How to avoid:** Convert all uploads to 16kHz mono WAV via ffmpeg before processing.
**Warning signs:** Empty transcripts or crashes on webm input.

### Pitfall 5: pyannote 3.1 Slow on CPU
**What goes wrong:** Diarization takes 10x longer on CPU vs MPS on Apple Silicon.
**Why it happens:** pyannote 3.1 is pure PyTorch, benefits greatly from GPU/MPS acceleration.
**How to avoid:** Always use `pipeline.to(torch.device("mps"))` on M3 Mac. Falls back to CPU gracefully on other hardware.
**Warning signs:** 30-minute recording taking 20+ minutes to diarize.

### Pitfall 6: Speaker Label Consistency
**What goes wrong:** pyannote assigns labels like "SPEAKER_00", "SPEAKER_01" which change across runs.
**Why it happens:** Clustering is non-deterministic in label assignment.
**How to avoid:** Remap to "Speaker 1", "Speaker 2" etc. sorted by first appearance time.
**Warning signs:** Same speaker getting different labels in different segments.

## Code Examples

### Audio Format Conversion
```python
import subprocess
import os

def convert_to_wav(input_path: str, output_path: str) -> str:
    """Convert any audio/video format to 16kHz mono WAV for STT."""
    subprocess.run([
        "ffmpeg", "-y",
        "-i", input_path,
        "-ar", "16000",      # 16kHz sample rate
        "-ac", "1",          # mono
        "-c:a", "pcm_s16le", # 16-bit PCM
        output_path
    ], check=True, capture_output=True)
    return output_path
```

### Upload Endpoint
```python
from fastapi import FastAPI, UploadFile, File
from uuid import uuid4
import aiofiles

@app.post("/recordings")
async def upload_recording(file: UploadFile = File(...)):
    job_id = str(uuid4())

    # Save uploaded file to disk immediately (before response)
    upload_path = f"uploads/{job_id}_{file.filename}"
    async with aiofiles.open(upload_path, "wb") as f:
        content = await file.read()
        await f.write(content)

    # Initialize job state
    jobs[job_id] = {
        "status": "pending",
        "file_path": upload_path,
        "original_filename": file.filename,
    }

    # Enqueue for processing
    await job_queue.put(job_id)

    return {"id": job_id}
```

@app.get("/recordings/{job_id}/status")
async def get_status(job_id: str):

### Speaker Statistics Calculation
```python
def calculate_speaker_stats(segments: list[dict]) -> list[dict]:
    """Calculate talk time percentage and utterance count per speaker."""
    speaker_times = {}
    speaker_counts = {}
    total_time = 0

    for seg in segments:
        speaker = seg["speaker"]
        duration = seg["end"] - seg["start"]
        speaker_times[speaker] = speaker_times.get(speaker, 0) + duration
        speaker_counts[speaker] = speaker_counts.get(speaker, 0) + 1
        total_time += duration

    # Filter speakers with <1% talk time
    stats = []
    for speaker, time in speaker_times.items():
        pct = (time / total_time * 100) if total_time > 0 else 0
        if pct >= 1.0:  # Locked decision: filter <1% speakers
            stats.append({
                "label": speaker,
                "talk_time_pct": round(pct, 1),
                "utterance_count": speaker_counts[speaker]
            })

    return sorted(stats, key=lambda s: s["talk_time_pct"], reverse=True)
```

## Open Questions

1. **Moonshine Voice TranscriptLine confidence scores**
   - What we know: TranscriptLine objects contain timing and text. Documentation mentions confidence but API details are sparse.
   - What's unclear: Whether confidence is exposed per-line or only available at model level.
   - Recommendation: Test during implementation. If not available, omit confidence from segments or use a placeholder of 1.0.

2. **pyannote model choice: 3.1 vs community-1**
   - What we know: community-1 is newer and better out-of-box. 3.1 requires HuggingFace token. community-1 may be more permissive.
   - What's unclear: Whether community-1 requires HF token, exact performance on M3.
   - Recommendation: Try community-1 first (better accuracy). Fall back to 3.1 if issues arise.

3. **Moonshine Voice built-in speaker identification maturity**
   - What we know: TranscriptLine has a speaker_id field. Documentation says speaker ID is built-in.
   - What's unclear: Quality/accuracy for meeting recordings with 2-3 speakers.
   - Recommendation: Try Moonshine's built-in speaker ID first during implementation. If accuracy is insufficient, fall back to pyannote. Plan code to support both approaches.
