<task type="auto">
  <name>Task 2: Build audio recording pipeline with crash recovery and global FAB</name>
  <files>src/lib/audio/chunk-store.ts, src/lib/audio/recovery.ts, src/stores/recording-store.ts, src/hooks/use-audio-recorder.ts, src/components/recording/recording-fab.tsx, src/app/(dashboard)/layout.tsx, src/app/(dashboard)/page.tsx</files>
  <action>
1. Create `src/lib/audio/chunk-store.ts` -- IndexedDB audio chunk persistence using `idb`:
   - Database name: `allure-audio`, store name: `chunks`, version 1
   - Use a compound index on `recordingId` for efficient querying
   - `saveAudioChunk(recordingId: string, chunk: Blob): Promise<void>` -- stores chunk with timestamp
   - `getAudioChunks(recordingId: string): Promise<Blob[]>` -- returns chunks sorted by timestamp
   - `clearAudioChunks(recordingId: string): Promise<void>` -- deletes all chunks for a recording
   - `getIncompleteRecordingIds(): Promise<string[]>` -- returns recordingIds that still have chunks (for recovery)

2. Create `src/stores/recording-store.ts` -- Zustand store with persist middleware:
   - State: `isRecording`, `currentRecordingId`, `startedAt` (timestamp), `elapsedSeconds`
   - Actions: `startRecording(id: string)`, `stopRecording()`, `setElapsed(seconds: number)`, `reset()`
   - Persist to localStorage with key `allure-recording`
   - On hydration, if `isRecording` is true but no active MediaRecorder, this indicates a crash -- flag for recovery

3. Create `src/lib/audio/recovery.ts`:
   - `checkForRecovery(): Promise<{hasRecovery: boolean, recordingIds: string[]}>` -- checks Zustand persisted state + IndexedDB for incomplete recordings
   - `recoverRecording(recordingId: string): Promise<Blob | null>` -- reassembles chunks from IndexedDB into a single Blob, returns null if no chunks found
   - `discardRecovery(recordingId: string): Promise<void>` -- clears chunks and resets store

4. Create `src/hooks/use-audio-recorder.ts`:
   - Uses `useRecordingStore` for state management
   - `startRecording()`: calls `getUserMedia({audio: true})`, creates MediaRecorder with `audio/webm;codecs=opus`, starts with `timeslice=3000` (3s chunks), stores each chunk via `saveAudioChunk` in `ondataavailable`
   - `stopRecording()`: stops MediaRecorder, in `onstop` assembles final blob from IndexedDB chunks, saves complete recording file to a temporary location (for now just holds the blob in memory/state -- filesystem save happens in Plan 02 when SQLite is ready), clears IndexedDB chunks, resets store
   - MediaRecorder instance stored in a module-level ref (NOT in React state) so it survives component re-renders and navigation. Per research Pitfall 4: the FAB lives in root layout which never unmounts, but the module-level ref is extra safety
   - Elapsed time: useEffect with setInterval updating every 1s based on `startedAt`
   - Error handling: catch `getUserMedia` rejection (mic denied), MediaRecorder errors. Use sonner toast for errors
   - On mount, run crash recovery check. If incomplete recording found, show a toast offering to recover or discard

5. Create `src/components/recording/recording-fab.tsx`:

   - Not recording: shows Mic icon (lucide-react), primary background color
   - Recording: transforms to red pulsing dot (`animate-pulse`, `bg-red-500`), shows Square icon + elapsed time formatted as `M:SS`
   - Click toggles start/stop via `useAudioRecorder`
   - Must be a client component (`'use client'`)
