1. **src/types/outcome.ts** -- Extend the Task interface and add supporting types:
   - Add `TaskStatus = 'todo' | 'in_progress' | 'done'` type alias
   - Add `TaskPriority = 'low' | 'medium' | 'high'` type alias
   - Extend Task interface with: `priority: TaskPriority`, `dueDate: string | null`, `assignee: string | null`, `tags: string[]`, `updatedAt: string`
   - Make `sourceOutcomeId`, `sourceRecordingId`, `backlink` nullable (string | null) since manually created tasks won't have these
   - Add `TaskFilters` interface: `{ status?: string | null; search?: string | null }`
   - Add `CreateTaskInput` interface: `{ title: string; detail?: string; priority?: TaskPriority; dueDate?: string | null; assignee?: string | null; tags?: string[] }`
   - Add `UpdateTaskInput` interface: `{ title?: string; detail?: string; status?: TaskStatus; priority?: TaskPriority; dueDate?: string | null; assignee?: string | null; tags?: string[] }`

2. **src/lib/db/schema.sql** -- Update the tasks CREATE TABLE statement directly (FYP project, no production data concern). Replace the existing CREATE TABLE tasks with:
   ```sql
   CREATE TABLE IF NOT EXISTS tasks (
     id TEXT PRIMARY KEY,
     title TEXT NOT NULL,
     detail TEXT NOT NULL DEFAULT '',
     source_outcome_id TEXT,
     source_recording_id TEXT,
     backlink TEXT,
     status TEXT NOT NULL DEFAULT 'todo',
     priority TEXT NOT NULL DEFAULT 'medium',
     due_date TEXT,
     assignee TEXT,
     tags TEXT NOT NULL DEFAULT '[]',
     created_at TEXT NOT NULL DEFAULT (datetime('now')),
     updated_at TEXT NOT NULL DEFAULT (datetime('now')),
     FOREIGN KEY (source_outcome_id) REFERENCES outcomes(id),
     FOREIGN KEY (source_recording_id) REFERENCES recordings(id)
   );
   ```
   Note: User may need to delete the existing DB file (`allure.db` or similar) for the new schema to take effect, since CREATE TABLE IF NOT EXISTS won't alter an existing table. Add a comment in schema.sql noting this.

3. **src/lib/db/tasks.ts** -- Extend with full CRUD:
   - Update `TaskRow` interface to include `priority`, `due_date`, `assignee`, `tags` columns
   - Update `rowToTask()` to map new columns (JSON.parse tags, camelCase transform for due_date -> dueDate)
   - Update existing `createTask()`: accept optional priority/dueDate/assignee/tags fields, generate `crypto.randomUUID()` for id if not provided, default priority to 'medium', default tags to '[]'
   - Keep backward compatibility: existing createTask callers (promote flow) pass sourceOutcomeId etc., new callers (manual creation) pass just title
   - Add `listTasks(filters?: { status?: string | null; search?: string | null }): Task[]` -- query with optional WHERE clauses, ORDER BY priority (high=1, medium=2, low=3) then created_at DESC
   - Add `updateTask(id: string, data: Partial<{title, detail, status, priority, dueDate, assignee, tags}>): Task | null` -- UPDATE only provided fields, set updated_at to datetime('now'), return updated task. JSON.stringify tags on write.
   - Add `deleteTask(id: string): boolean` -- DELETE FROM tasks WHERE id = ?, return true if rowsChanged > 0

1. **src/app/api/tasks/route.ts** -- Follow the recordings route pattern:
   - `GET`: Read `status` and `search` query params from `request.nextUrl.searchParams`, call `listTasks({ status, search })`, return JSON array
   - `POST`: Parse JSON body, validate with zod schema (title required string min 1, detail optional string, priority optional enum, dueDate optional string, assignee optional string, tags optional string array). Call `createTask()` with validated data (generate id via `crypto.randomUUID()`). Return 201 with task object.
   - Import from `@/lib/db/tasks`

2. **src/app/api/tasks/[id]/route.ts** -- Follow the recordings/[id] route pattern:
   - `GET`: Extract id from params, call `getTask(id)`, return 404 if null, else return JSON
   - `PATCH`: Extract id from params, parse JSON body, validate with zod (all fields optional: title, detail, status, priority, dueDate, assignee, tags). Call `updateTask(id, validated)`. Return 404 if null, else return updated task.
   - `DELETE`: Extract id from params, call `deleteTask(id)`. Return 404 if false, else return 204 No Content.

3. **src/hooks/use-tasks.ts** -- Follow use-recordings.ts pattern exactly:
   - `useTasks(filters?: TaskFilters)`: useQuery with queryKey `["tasks", filters ?? "all"]`, fetches from `/api/tasks` with query params built from filters
   - `useCreateTask()`: useMutation calling apiClient.post to `/api/tasks`, invalidates `["tasks"]` on success, shows toast("Task created") via sonner
   - `useUpdateTask()`: useMutation calling apiClient.patch to `/api/tasks/${id}`, invalidates `["tasks"]` on success. Accept `{ id: string } & UpdateTaskInput`.
   - `useDeleteTask()`: useMutation calling apiClient.delete to `/api/tasks/${id}`, invalidates `["tasks"]` on success, shows toast("Task deleted")
   - Add `"use client"` directive at top
   - Import types from `@/types/outcome`, apiClient from `@/lib/api/client`
