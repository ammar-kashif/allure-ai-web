   - Use `useSortable` hook from @dnd-kit/sortable with task.id as identifier
   - Apply `transform` and `transition` via CSS utility from @dnd-kit/utilities
   - Card content: task title (font-medium, text-sm), priority as a small colored dot (not full badge -- compact per user decision), due date in muted small text if set (format with date-fns)
   - Card styling: Card component with compact padding (p-3), hover:shadow-sm, cursor-grab, bg-card border rounded-lg
   - Clicking the card calls `onTaskClick(task)` prop (opens detail panel)
   - Set `data: { status: task.status }` on the sortable for column identification
   - When `isDragging` is true, reduce opacity to 0.5

3. **src/components/task/task-kanban-column.tsx** -- Droppable column:
   - Accept `status: TaskStatus`, `title: string`, `tasks: Task[]`, `onTaskClick` props
   - Use `useDroppable` hook with `id: status` so empty columns can receive drops
   - Wrap tasks in `SortableContext` with `verticalListSortingStrategy` and `items: tasks.map(t => t.id)`
   - Column header: status title + task count badge (e.g., "To Do (3)")
   - Column styling: flex-1 min-w-[280px] bg-muted/30 rounded-lg p-3, min-h-[200px] for empty column drop target
   - Render TaskKanbanCard for each task
   - If no tasks, show subtle "No tasks" placeholder text (muted, centered)

4. **src/components/task/task-kanban-view.tsx** -- Board wrapper:
   - Accept `onTaskClick: (task: Task) => void` and `onCreateClick: () => void` props
   - "+ New Task" button at top-right (same as list view, calls onCreateClick)
   - Fetch tasks via `useTasks()` (no filter -- board shows all statuses)
   - Group tasks into 3 arrays by status: todo, in_progress, done
   - Track `activeId` state (string | null) for DragOverlay
   - Wrap columns in `DndContext` with `collisionDetection={closestCorners}`:
     - `onDragStart`: set activeId from event.active.id
     - `onDragEnd`: determine target column status. Logic:
       - If `over` is null, do nothing
       - If `over.id` matches a status string ('todo', 'in_progress', 'done'), that's the target column
       - Otherwise, find which column the `over` item belongs to (look up the task's current status)
       - If the target status differs from the dragged task's current status, call `useUpdateTask().mutate({ id: activeId, status: targetStatus })`
     - Clear activeId
   - Render 3 KanbanColumn components in a flex row (gap-4)
   - Render DragOverlay: when activeId is set, show a clone of the active card (find task by activeId, render TaskKanbanCard without sortable)
   - Use optimistic update pattern: in useUpdateTask's onMutate, manually update the query cache to move the card immediately, then onSettled refetch. This prevents visual lag.

5. **src/components/task/task-page.tsx** -- Wire Board tab:
   - Import TaskKanbanView
   - Replace the "Kanban board coming soon" placeholder in the Board tab with `<TaskKanbanView onTaskClick={handleTaskClick} onCreateClick={handleCreateClick} />`
   - Ensure selectedTaskId and createDialogOpen state flows to both views
