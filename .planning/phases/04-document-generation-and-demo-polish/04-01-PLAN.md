  <action>
    **Backend (document_generation.py):**
    Create `backend/document_generation.py` with two functions:

    1. `generate_prd(job_id: str, app_state: object) -> str` -- fetches job outcomes from storage, builds a prompt using PRD_SYSTEM_PROMPT (see RESEARCH.md for recommended prompt), formats outcomes as structured input, calls `app_state.llm.create_chat_completion(messages=messages, temperature=0.3, max_tokens=4096)` with NO response_format (plain text output for prose), returns the generated markdown string.

    2. `generate_diagram(job_id: str, diagram_type: str, app_state: object) -> str` -- fetches job outcomes, selects USERFLOW_SYSTEM_PROMPT or ERD_SYSTEM_PROMPT based on `diagram_type` ("user_flow" or "erd"), calls LLM with `temperature=0.2, max_tokens=2048`, returns raw Mermaid code string. Use the prompt templates from RESEARCH.md.

    Helper: `format_outcomes_for_generation(outcomes: list) -> str` -- formats outcomes as numbered list with type, title, detail, and confidence for the LLM prompt.

    **Backend (main.py):**
    Add two new endpoints to `main.py`:

    1. `POST /recordings/{job_id}/generate-prd` -- validates job exists and has outcomes (return 404/400 otherwise), calls `await asyncio.to_thread(generate_prd, job_id, app.state)`, returns `{"content": content, "title": f"PRD - {job.get('original_filename', 'Recording')}"}`. Use synchronous-in-thread pattern (not job queue) per RESEARCH.md Pattern 2.

    2. `POST /recordings/{job_id}/generate-diagram` -- accepts JSON body with `{"type": "user_flow" | "erd"}`, validates job exists and has outcomes, calls `await asyncio.to_thread(generate_diagram, job_id, body["type"], app.state)`, returns `{"content": content, "type": body["type"], "title": f"{type_label} - {job.get('original_filename', 'Recording')}"}` where type_label is "User Flow" or "ERD".

    **Frontend SQLite (schema.sql):**
    Add documents table to the end of schema.sql:
    ```sql
    CREATE TABLE IF NOT EXISTS documents (
      id TEXT PRIMARY KEY,
      title TEXT NOT NULL,
      type TEXT NOT NULL CHECK(type IN ('prd', 'user_flow', 'erd')),
      content TEXT NOT NULL,
      source_recording_id TEXT NOT NULL,
      created_at TEXT NOT NULL DEFAULT (datetime('now')),
      FOREIGN KEY (source_recording_id) REFERENCES recordings(id)
    );
    ```

    **Frontend DB module (documents.ts):**
    Create `src/lib/db/documents.ts` following the exact pattern from `tasks.ts`:
    - `Document` interface: id, title, type ("prd"|"user_flow"|"erd"), content, sourceRecordingId, createdAt
    - `DocumentRow` internal interface with snake_case columns
    - `rowToDocument` mapper
    - `createDocument(data)` -- generates UUID, inserts, returns document
    - `getDocument(id)` -- returns Document | null
    - `listDocuments(filters?: { type?: string | null })` -- optional type filter, ORDER BY created_at DESC
    - `countDocuments()` -- returns number (for dashboard stat)

    **Frontend API routes:**
    1. `src/app/api/documents/route.ts` -- GET handler: reads optional `type` query param, calls `listDocuments({ type })`, returns JSON array.
    2. `src/app/api/documents/[id]/route.ts` -- GET handler: calls `getDocument(id)`, returns 404 if not found, else JSON document.
    3. `src/app/api/recordings/[id]/generate-prd/route.ts` -- POST handler: proxies to `http://localhost:8000/recordings/${id}/generate-prd`, on success stores result via `createDocument({ title, type: "prd", content, sourceRecordingId: id })`, returns 201 with created document. On backend error, return appropriate status.
    4. `src/app/api/recordings/[id]/generate-diagram/route.ts` -- POST handler: reads `{ type }` from request body, proxies to `http://localhost:8000/recordings/${id}/generate-diagram` with the body, on success stores via `createDocument({ title, type: body.type, content, sourceRecordingId: id })`, returns 201. Use zod to validate the type field is "user_flow" or "erd".
