  <action>
  In backend/audio_utils.py:
  1. Add ".mov" to ALLOWED_EXTENSIONS set
  2. Add a new function `detect_no_audio_track(input_path: str) -> bool` that uses ffprobe to check if the file has an audio stream. Run: `ffprobe -v error -select_streams a -show_entries stream=codec_type -of csv=p=0 {input_path}`. If stdout is empty after strip, the file has no audio track — return True. Wrap in try/except for subprocess errors (return False on error, let ffmpeg fail later with a more descriptive message).

  In backend/main.py POST /recordings endpoint:
  1. Add file size validation at the top of the handler, after reading file_bytes: if `len(file_bytes) > 500 * 1024 * 1024` raise HTTPException(413, "File too large. Maximum size is 500MB.")
  2. After saving the original file but BEFORE convert_to_wav, call `detect_no_audio_track(original_path)`. If True, clean up the original file and raise HTTPException(422, "This video has no audio — nothing to transcribe").
  3. After successful convert_to_wav, delete the original uploaded file (video) to save disk space: `os.remove(original_path)`. Only delete if original_path != wav_path (i.e., don't delete if the upload was already a WAV).
  4. Update the error detail for conversion failure from "Audio conversion failed" to "File conversion failed — the file may be corrupt or use an unsupported codec".
