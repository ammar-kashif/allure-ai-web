## Cross-Phase Integration Issues

### CRITICAL: Assignment-to-Backend Upload (MISSING-01)

**From:** Phase 1 `useAssignProject` → **To:** Phase 1.1 FastAPI
**Issue:** `PATCH /api/recordings/{id}` only updates local DB (`projectId` + `status: processing`). Audio is never forwarded to FastAPI. `backendId` is never set.
**Impact:** Any recording assigned to a project after initial save stays in `processing` forever. Downstream operations requiring `backendId` (`/transcript`, `/outcomes`, `/extract`, `/generate-prd`, `/generate-diagram`) return HTTP 400.
**Affected:** REC-05, STT-01, STT-04 (and transitively EXT-01-07, DOC-01-03 for assign-path recordings)
**Note:** FAB path (`POST /api/recordings`) correctly proxies to FastAPI immediately — recordings created via FAB get `backendId` set.

### MODERATE: Promoted Tasks Have Empty Titles (MISSING-02)

**From:** Phase 2 promote route → **To:** Phase 3 task management
**Issue:** `src/app/api/outcomes/[outcomeId]/promote/route.ts` hardcodes `title: ""` and `detail: ""`. Backend `PromoteResponse` only returns `{ id, type, backlink }` — outcome text is never fetched from SQLite.
**Impact:** Every promoted task/requirement appears with empty title in list, Kanban, and detail panel.
**Affected:** EXT-05, EXT-06, TASK-01, TASK-02

### MINOR: Dashboard Stats Inaccuracy (MISSING-03)

**From:** Phase 2.1 `use-dashboard-stats.ts` → **To:** Phase 3 tasks
**Issue:** "Tasks Created" counts `promoted outcomes`, not actual task rows. Misses manually created tasks, miscounts promoted requirements.
**Affected:** No explicit requirement, but crosses Phase 2/3 integration.
