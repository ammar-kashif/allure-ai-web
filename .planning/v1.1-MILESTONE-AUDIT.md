## Integration Check

**Issues:** 2

### INT-01: Fragile SpeakerStats model (Low)

**Affected:** SPKR-01, SPKR-02
**File:** `backend/models.py`

`SpeakerStats` Pydantic model is missing `custom_label` and `role` fields. The transcript endpoint returns a raw dict (bypassing model validation), so these fields pass through today. Adding `response_model=TranscriptResponse` in the future would silently drop both fields, breaking speaker rename and role assignment.

**Fix:** Add `custom_label: str = ""` and `role: str = ""` to `SpeakerStats` in `models.py`.

### INT-02: Post-recording dialog backendId race condition (Medium)

**Affected:** RUX-02, DOC-02, GEN-02
**File:** `src/app/api/recordings/[id]/documents/route.ts`

When a user uploads documents from the post-recording dialog, the route checks `recording.backendId` before forwarding to the Python backend for text extraction. If the user saves the dialog before the parallel audio upload completes (which sets `backendId`), documents are saved to disk but never forwarded for extraction. Phase 8 context injection would then have no extracted text for those documents.

**Fix:** Either retry extraction when `backendId` becomes available, or queue the forwarding.
